# statverify

Поиск внутренних противоречий в статистических утверждениях научных
статей. Сообщённые `t`, `df`, `p`, размеры эффекта и доверительные
интервалы взаимно переопределены — из тройки `(t, df, p)` свободны
только двое, — поэтому несогласованность между ними обнаружима
арифметикой, без участия языковой модели в вынесении вердикта.

**Состояние: ранняя стадия.** Работает одно отношение из девяти, на
двустороннем t-тесте, с регексповым извлечением. Все приведённые числа
получены прогоном кода на порождённой арифметикой разметке, а не оценкой.
Раздел «Чего эти числа не значат» ниже — обязателен к прочтению.

## Чем отличается от существующих систем

| | Что делает | Ограничение |
|---|---|---|
| statcheck | сверяет тройку (статистика, df, p) | точность около 60% на реальной литературе, и теряется она на извлечении, а не на арифметике |
| ARA (2026) | LLM судит корректность | цепочка оканчивается на суждении модели: модель проверяют моделью |
| GRIM / SPRITE | гранулярность средних | только целочисленные ограниченные шкалы |

Отправная точка здесь не новая арифметика, а два места, где эти системы
уступают:

**Завершаемость.** Решение о наличии дефекта принимает детерминированный
код. Модель участвует только в извлечении и классификации.

**Провенанс.** Число попадает в решатель, только если прослежено до
конкретного места в исходнике: та же строка по тому же смещению, внутри
границ того же утверждения, с маркером роли вплотную перед ней. Значение
без провенанса не «менее надёжно» — оно не существует.

Второе даёт измеримую разницу. Проверка присутствия значения в тексте
(как в предыдущей версии проекта) ловит выдумывание, но слепа к взятию
числа не оттуда — а модель промахивается именно так, беря настоящее
число из настоящего, но чужого места. На семи размеченных случаях:
проверка присутствия даёт 4 верных вердикта из 7, проверка провенанса —
7 из 7 (`scripts/compare_with_prior_guard.py`).

## Установка и запуск

Рантайму зависимости не нужны — только Python 3.9+.

```bash
git clone <repo> && cd statverify

python3 run_tests.py                  # 215 тестов, без зависимостей
python3 scripts/run_step1.py          # отчёт: извлечение и охранник
python3 scripts/run_step2.py          # отчёт: решатель, интервалы, локализация
python3 scripts/demo_discrimination.py
```

С установленным pytest (плюс scipy как оракул для ядра):

```bash
pip install -e ".[test]"
pytest
```

## Пример

```python
from statverify import extract, admit, verify_claim

text = "Scores differed across conditions, t(99) = 2.45, p = .001."

doc = extract(text)
for claim in doc.claims:
    ok, results = admit(claim, doc.source)      # охранник L2
    if not ok:
        print("извлечение не подтверждено:", results[0].reason)
        continue
    print(verify_claim(claim).line())
# INCONSISTENT [R2a] — противоречие есть, виновник не выделен; допустимы: t, p
```

Двусторонний `p` при `t = 2.45` и `df = 99` равен `.0160`, а сообщено
`.001`. Почему виновник не выделен — см. «Известное ограничение».

## Устройство

| Слой | Что делает | Статус |
|---|---|---|
| L0 | режет текст на утверждения; их границы — то, за что переменные не ходят | готово |
| L1 | типизированное извлечение: значение, литерал, span, точность записи, знак отношения, кандидатные разборы | готово, регекс |
| L1.5 | классификация дизайна теста; при неуверенности — отказ, а не догадка | не сделано |
| L2 | охранник: границы, литерал по смещению, значение из литерала, маркер роли, сверка отношения | готово |
| L3 | каталог отношений, решаемых в любую сторону | готово, 1 из 9 |
| L4 | интервальная арифметика: `.016` это `[.0155, .0165)`, а не точка | готово |
| L5 | локализация: какая из переменных врёт | готово, упирается в плотность каталога |
| L6 | мягкие эвристики — приоритет на проверку, не вердикт | не сделано |
| L7 | вердикт и абстенция | готово частично |

Подробно, с обоснованием каждого решения: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Измеренное

Извлечение и охранник (`scripts/run_step1.py`):

| | |
|---|---|
| размеченных утверждений найдено | 34 / 34 |
| ложных отказов охранника | 0 из 100 проверок |
| искусственная порча поймана | 180 / 180, каждая своим критерием |

Решатель (`scripts/run_step2.py`):

| | |
|---|---|
| ложных срабатываний на согласованных | 0 / 38 |
| обнаружено на несогласованных | 38 / 38 |
| локализовано до одной переменной | 0 |
| `df` оправдан нормальным пределом | 36 / 38 |

Отдельно: на случаях с грубо записанным `t` интервальный подход и
точечная сверка расходятся 4 раза из 7, и все четыре — ложные тревоги
точечной сверки. При `t(99) = 2.5` истинная статистика занимает
`[2.45, 2.55)`, которому отвечает `p` от `.0122` до `.0160` — почти
треть порядка.

## Известное ограничение: локализация

Спецификация обещала выход вида «врёт `df`, следует 99, сообщено 98».
При единственном отношении задача недоопределена: три переменные, одна
связь, виновной может быть любая. Все 38 обнаружений дают `AMBIGUOUS`.
Нормальный предел на двусторонний `p` оправдывает `df` в 95% случаев,
сужая круг с трёх до двух, но не до одного.

Это свойство графа, а не дефект алгоритма. Механизм заработает при
уплотнении каталога: пусть добавлено `R5: t = оценка / SE`. Если врёт
`p`, гипотеза «врёт p» чинит R2a и ничего не ломает, а «врёт t» чинит
R2a, но ломает R5. Эта асимметрия и выделяет виновника; одного отношения
для неё принципиально недостаточно.

Ограничение закреплено тестом
`tests/test_verify.py::test_localization_is_currently_ambiguous`, который
обязан упасть, когда локализация заработает.

## Чего эти числа не значат

**Корпус и извлекатель написаны под одну задачу.** 34 из 34 означают,
что регекс справляется с предусмотренными для него форматами, и ничего
не говорят о реальных статьях.

**Доля прохождения охранника высока по построению.** При регексповом
извлечении span берутся из позиций групп совпадения. Осмысленно измерена
не она, а чувствительность к порче: виды 5–8 сделаны правдоподобными —
литерал настоящий и лежит по месту, поэтому проверки литерала и значения
на них слепы, и ловят границы утверждения и маркер роли. Это свойство
самого охранника, не зависящее от извлекателя впереди.

**Statcheck воспроизведён по логике, а не по опубликованным
результатам.** Настоящего statcheck (пакет R) в прогоне не было.

**Главный риск не измерен.** Сколько честных извлечений охранник
забракует на живом тексте — неизвестно, и не станет известно до
появления модельного извлекателя.

## Что дальше

1. Отношения `R5: t = оценка / SE` и `R4: доверительный интервал` — от
   классификации дизайна не зависят, доступны сразу, и именно они
   превращают `AMBIGUOUS` в локализацию.
2. L1.5, классификация дизайна — разблокирует остальной каталог.
3. Модельный извлекатель и замер доли ложных отказов охранника.
4. Петля переизвлечения — только после пункта 3.
5. Размеченный набор от 200 реальных случаев. До него любые сквозные
   проценты остаются сочинёнными.
