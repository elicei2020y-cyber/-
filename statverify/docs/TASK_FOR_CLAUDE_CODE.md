## 1. Правила, которые нельзя нарушать

Они не стилистические. Каждое закрывает конкретный способ, которым
верификатор превращается в генератор уверенной чепухи.

**1.1. Решение о наличии дефекта принимает код, не модель.** Модель
допускается только в извлечении (L1) и классификации дизайна (L1.5).
Если появляется соблазн спросить у модели «это ошибка?» — значит,
не хватает отношения в каталоге, и делать надо его.

**1.2. Ожидаемое значение никогда не уходит обратно в извлечение.**
Формулировка обратной связи — «слот `df`, возможно, взят из другого
теста, переизвлеки», никогда «`df` должно быть 99». Иначе модель
перепишет значение под инвариант, всё позеленеет, а настоящая ошибка
статьи отмоется в согласованную таблицу — и постфактум это не заметить.

**1.3. Отношение, верное «обычно», не вносится в каталог.** Правило,
работающее в большинстве случаев, в верификаторе хуже отсутствующего:
его ложные срабатывания неотличимы от находок. Нет уверенности в
применимости — `UNVERIFIABLE`, а не «применим и посмотрим».

**1.4. Отношение обязано быть монотонным по каждому аргументу**
(при фиксированных остальных). Распространение интервалов в
`relations.py` идёт по углам входного бокса, и для немонотонной связи
это даёт заниженный интервал, то есть ложные срабатывания. Нужна
немонотонная связь — сначала меняй способ распространения, потом вноси.

**1.5. Интервал никогда не расширяется, чтобы убрать ложное
срабатывание.** Ширина задаётся точностью записи и ничем больше.
Расширение «на всякий случай» снижает чувствительность на всех статьях
ради корректности на части.

**1.6. Точность не публикуется без доли абстенций.** 95% точности при
отказе на 80% статей хуже, чем 80% при отказе на 10%.

**1.7. `CONSISTENT` формулируется как «внутренних противоречий не
обнаружено», не «верно».** Статья бывает безупречно согласованной и
полностью неправильной.

**1.8. Порог теста выводится из требования задачи, а не двигается до
прохождения.** Если тест не проходит — сначала найди источник, потом
решай. Пример правильного рассуждения — в `tstats.py`, комментарий о
точности.

## 2. Задача 1 — отношения R5 и R4 (приоритет)

**Зачем.** Сейчас локализация выдаёт `AMBIGUOUS` в 100% случаев: три
переменные, одно отношение, виновной может быть любая. Механизм
выделения виновника требует, чтобы гипотеза чинила одно отношение и
ломала другое, — для этого нужен второй, пересекающийся по переменным.
R5 и R4 от классификации дизайна не зависят, поэтому доступны сразу.

**R5: `t = оценка / SE`**

```python
R5 = Relation(
    key="R5", vars=("est", "se", "t"),
    text="t = оценка / SE",
    designs=("two_tailed_t",),          # применимо шире, расширить при R2b
    solvers={"t":   lambda k: k["est"] / k["se"],
             "est": lambda k: k["t"] * k["se"],
             "se":  lambda k: k["est"] / k["t"] if k["t"] else None},
)
```

Монотонность: `est/se` монотонна по `est` при фиксированном `se > 0`
и монотонна по `se` при фиксированном `est`. Условие 1.4 выполнено,
углы годятся. Добавь `"se": Interval(TINY, 1e9)` и `"est"` в `DOMAIN`.

**R4: доверительный интервал.** Разложить на две связи через полуширину
и центр — так каждая остаётся монотонной:

```
центр:      (ci_lo + ci_hi) / 2 = est
полуширина: (ci_hi - ci_lo) / 2 = t_crit(df, alpha) * se
```

`t_crit(df, alpha)` уже есть: это `tstats.t_from_p(alpha, df)`. При
отсутствии явного уровня брать `alpha = 0.05` и **записывать это
допущение в вердикт**, а не молча.

**Извлечение.** Расширить `extract.py` на форматы:
`b = 0.45, SE = 0.12` · `β = .45 (SE = .12)` · `M = 3.2, SD = 1.1` ·
`95% CI [0.21, 0.69]` · `95% CI = 0.21 to 0.69`.
Маркеры ролей для новых слотов добавить в `guard.ROLE_MARKER` — без
этого C3 отвергнет их все.

**Критерий приёмки.** Написать `run_step3.py`, который:

1. Строит утверждения, где все семь величин `(t, df, p, est, se, ci_lo,
   ci_hi)` взаимно согласованы. Согласованность порождать арифметикой:
   задать `est`, `se`, `df`; вычислить `t = est/se`, `p` из `(t, df)`,
   границы CI из `t_crit`. Не размечать руками.
2. Портит ровно одну величину за раз, достаточно сильно, чтобы выйти
   за интервал.
3. Проверяет, что `verify_claim` возвращает `INCONSISTENT` и что
   `verdict.var` совпадает с испорченной величиной.

Цель: **доля верной локализации ≥ 90%** при **нуле ложных срабатываний**
на неиспорченных. Обе цифры печатать. Если локализация верна, но ниже
90% — не подгоняй пороги правдоподобия, разберись, какие гипотезы
остаются допустимыми и почему граф их не различает.

## 3. Задача 2 — L1.5, классификация дизайна

**Зачем.** Разблокирует R1a, R1b, R2b, R3 — все они ветвятся по типу
теста. Это единственное место, где решение принимает модель, поэтому
измеряется отдельно.

**Что определять:** парный / одновыборочный / независимые выборки;
двусторонний или односторонний; целочисленна ли шкала (гейт для GRIM).

**Контракт:** возвращать `(design: str, confidence: float)`. Ниже порога —
`design = "unknown"`, и `verify_claim` обязан выдать
`UNVERIFIABLE(design_unknown)`. Порог подобрать по измеренной кривой,
а не назначить.

**Критерий приёмки.** Размеченный набор минимум 60 утверждений с
известным дизайном. Печатать: точность на неотказанных, долю отказов,
и отдельно — **долю случаев, где классификатор уверенно ошибся**
(confidence выше порога, дизайн неверный). Последнее число важнее двух
первых: уверенная ошибка подставляет не ту формулу и даёт ложное
срабатывание, которое выглядит как находка.

## 4. Задача 3 — модельный извлекатель

**Зачем.** Регексповый извлекатель покрывает форматы, придуманные для
него. Главный незамеренный риск проекта — сколько честных извлечений
охранник забракует на живом тексте.

**Ключевая деталь реализации.** Не проси модель возвращать смещения
символов — она их не считает. Пусть возвращает **литерал плюс короткий
уникальный контекст**, а span находит детерминированный код поиском
этого контекста в исходнике:

```python
# модель вернула: {"name": "df", "literal": "99", "context": "t(99) = 2.45"}
idx = source.find(context)
if idx == -1 or source.find(context, idx + 1) != -1:
    → отказ охранника: контекст отсутствует или неоднозначен
span = (idx + context.index(literal), ...)
```

Это переносит счёт символов на код и превращает «модель ошиблась в
смещении» в честный отказ охранника, а не в тихо неверный span.

**Контракт:** тот же, что у `extract.extract(source) -> Document`.
Слоты с `span`. Всё остальное в конвейере не меняется.

**Критерий приёмки — измерение ложных отказов через диагностический
режим.** Ради этого задача 1 делалась раньше. Для каждого извлечения,
забракованного охранником, прогнать его через отношения игнорируя отказ.
Если забракованный набор удовлетворяет R2a (и R5, если величины есть),
отказ почти наверняка ложный: вероятность случайно согласованной
неверной тройки пренебрежима. Печатать долю таких случаев — это и есть
оценка ложных отказов без ручной разметки.

Если доля выше 5% — ослаблять не пороги наугад, а конкретно: окно
маркера роли (`guard.WINDOW = 48`) и запрет на вклинившийся текст в
`ROLE_MARKER`. Каждое ослабление проверять прогоном `run_step1.py`:
чувствительность к порче обязана остаться 100%.

## 7. Ловушки, на которых уже спотыкались

**Банковское округление.** Встроенный `round()` в Python округляет
половину к чётному: `round(0.0165, 3)` даёт `0.016`, а не `0.017`.
`interval.py` работает округлением к ближайшему, поэтому в любой
разметке использовать `round_half_up` из `run_step2.py`, иначе получишь
искусственные расхождения на границах.

**Охранник проходит по построению при регексповом извлечении.** Span
берутся из позиций групп совпадения, поэтому C0, C1, C2 не могут не
пройти. Не принимай «100% прохождения» за свидетельство качества
охранника — осмысленна только чувствительность к порче (`corrupt.py`).

**Порчи должны быть правдоподобными.** Порча, которую ловит C1, ничего
не проверяет: C1 тривиален. Ценность в порчах, где литерал настоящий и
лежит по месту — тогда работать обязаны C0 и C3. При добавлении новых
слотов добавляй и порчи такого рода.

**`meet` возвращает `None` при пустом пересечении.** В `relations.solve`
это намеренно: `None` означает «такого значения переменной не существует»,
и локализация обязана на этом основании отвергнуть гипотезу. Не заменяй
на возврат неурезанного интервала — это была реальная ошибка при сборке.

**Нормальный предел даёт бесплатное оправдание `df`.** Двусторонний `p`
не опускается ниже `2(1−Φ(|t|))` ни при каком `df`. `tstats.df_from`
возвращает `None` в этом случае, и это содержательный ответ, не сбой.

**scipy — оракул, не рантайм.** `tstats.py` обязан оставаться без
внешних зависимостей. scipy импортируется только в `test_tstats.py`.

## 8. Как проверять свою работу

Перед тем как считать задачу сделанной:

1. Три существующих прогона проходят без изменения цифр (кроме тех,
   что задача должна была улучшить).
2. Новые отношения не сломали ложные срабатывания: `run_step2.py`
   раздел A по-прежнему даёт ноль.
3. Новые слоты имеют маркер роли в `guard.ROLE_MARKER` и порчу в
   `corrupt.py`.
4. Каждая новая цифра в отчёте прослеживается до прогона, который её
   породил. Оценок в отчётах нет.
5. Если что-то не заработало — это пишется прямо, с указанием причины.
   Проект уже потерял время на выдуманных процентах улучшения; худшее,
   что можно сюда добавить, — ещё одну необоснованную цифру.
